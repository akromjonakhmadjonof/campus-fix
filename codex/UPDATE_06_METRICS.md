# Update 06 data and metric definitions

The dashboard is campus-wide. Personal resolution credit and My Work remain on Staff Account. Analytics comes from one PostgreSQL statement, giving all metric cards, charts and rankings one consistent database snapshot.

## Reporting calendar

The 7, 30 and 90-day windows contain complete calendar days in `America/New_York`, matching next-intl's existing application time zone. The interval is half-open: midnight at the start is included and midnight today is excluded. PostgreSQL converts both boundaries to UTC for the stored timestamp columns, so daylight-saving changes retain correct local days. The date range is displayed explicitly. All periods use daily buckets, including zero days; this avoids partial-week comparisons. The current backlog and attention list are clearly labeled current snapshots, independent of the selected period.

## Metric definitions

| Metric                | Definition                                                                                                                                                                                                                                                                                                                          |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Current open          | Non-deleted reports currently Reported, Accepted or In Progress, regardless of creation date.                                                                                                                                                                                                                                       |
| Received              | Non-deleted reports created inside the reporting window.                                                                                                                                                                                                                                                                            |
| Resolved              | Unique non-deleted, non-rejected reports with a stored Resolved event in the window. For multiple historical completions, use the latest event within that window once.                                                                                                                                                             |
| Average resolution    | For that same resolved cohort, elapsed time from the most recent matching In Progress event to the selected Resolved event. A prior terminal event separates cycles. Events before report creation, negative durations and missing/ambiguous work starts are excluded from duration samples. The card shows the valid sample count. |
| Average time to start | Creation to first-ever In Progress event. Include only first starts inside the selected window and nonnegative intervals. Accepted does not reset the clock. The card shows the valid sample count.                                                                                                                                 |
| Upvotes recorded      | Successful persisted VoteEvent rows created inside the window, excluding deleted reports. Duplicate attempts do not create events. Undo preserves history; a subsequent successful new vote is a new event. Current confirmation badges continue to show active votes.                                                              |
| Location ranking      | Created-report cohort, rolled up recursively to exactly one top-level location. Includes buildings, outdoor areas and parking; no string-prefix assumptions or ancestor double counting.                                                                                                                                            |
| Issue ranking         | Created-report cohort grouped by actual issue-type records.                                                                                                                                                                                                                                                                         |
| Trends                | Daily created reports and daily latest selected resolutions. Series sums match their respective metric cards.                                                                                                                                                                                                                       |
| Hotspots              | Top five root locations by created-report volume, with each location's leading issue group and count. Ties use stable names/codes. This is a ranking, not a claim of statistical abnormality.                                                                                                                                       |
| Attention             | Deduplicated union of three oldest open requests, three most-confirmed open requests with votes, and three oldest requests still waiting to start. Reasons are explicit; no new priority score.                                                                                                                                     |

The live workflow still treats Resolved and Rejected as terminal. No reopening endpoint was added. Defensive historical-cycle handling is tested using imported-history fixtures: one report is counted once per selected window, using its latest completion and corresponding work cycle. A report rejected later is excluded from completion metrics. Missing duration samples produce an unavailable value, never a fabricated zero.

## Notifications and history

- Notifications reference the existing recipient Profile, the report, and exactly one uniquely constrained vote or status event. Actor kinds and notification types are enums. Actor/profile references stay on the server; the inbox DTO contains presentation data only.
- Successful new votes and their VoteEvent/notification writes share a serializable transaction. Bounded whole-transaction retries handle serialization conflicts. Duplicate inserts create neither event nor notification; self-votes remain forbidden.
- Status updates check the original version and permitted transition, then update the report, append the actor snapshot/history, create the notification and append the audit record in the same transaction. Losing concurrent changes return HTTP 409. The frontend refreshes the record and shows a translated conflict message.
- Actor display names are snapshots, rendered as escaped plain text. Unnamed reporters use the current locale's Guest Reporter label. Rejection notes are included. Actor names are not profile links; only the report title navigates.
- Inbox queries derive the recipient from the validated anonymous session. Pagination uses a bounded timestamp/UUID cursor. Read operations are recipient-scoped and idempotent. Mark All uses the server-provided observed timestamp so a notification arriving afterward remains unread.
- Existing approved anonymous-profile linking transfers inbox ownership with reports and sessions. Historical actor snapshots and vote events remain unchanged.
- The migration adds notifications, immutable vote events, actor-name snapshots and supporting indexes. Existing retained votes are backfilled into events without generating retrospective alerts. Withdrawn votes from before this migration cannot be reconstructed. Existing staff names are copied into the new history snapshot column within the migration transaction; actor IDs, event times and notes are preserved, and the immutable-history trigger is restored before commit.
- Reporter unread counts and previews refresh every 30 seconds when active, on focus and after reads. Older inbox pages do not poll. Native AppState foreground/background changes update TanStack's focus manager. Dashboard data uses a one-minute freshness window and focus/mutation invalidation, with no continuous dashboard polling.

The existing demo records are sufficient for charts. This update does not add accomplishments to existing staff accounts or reseed the demo database. New deterministic scenarios and worker identities are confined to the isolated test database. Future optional fixture seeds now record matching vote events and staff-name snapshots on newly inserted records.
