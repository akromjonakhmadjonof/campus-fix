# Three-minute CampusFix demonstration

Use seeded fictional reports and a CLI-created fictional maintenance worker. Start Next/API and PostgreSQL first. Keep a second private browser context ready for voting/pairing, and a staff tab signed in.

- **0:00–0:20:** Open Account. Explain the campus maintenance problem, pseudonymous profile and own recent reports.
- **0:20–0:55:** Create a fictional report. Select a real reference building/floor/room, issue group/type and exact object position; upload an illustrative object image.
- **0:55–1:20:** Show live possible matches and reasons. Confirm an existing report without creating one, then demonstrate Create anyway for a physically distinct object.
- **1:20–1:45:** Submit and view the persistent detail/photo. Open Account → See all. Show that a second independent context can vote but cannot edit.
- **1:45–2:25:** In staff Requests, open the report, inspect possible duplicates, Accept, Start work, and Resolve with a meaningful fictional note. Refresh the public view and show four dated milestones and the personal resolved list.
- **2:25–2:45:** Switch to Spanish and dark appearance. Show pairing code → second client request → initiating-client approval. Explain that browsers and WebViews do not automatically share identity.
- **2:45–3:00:** State limits: local demonstration, no university integration, fictional incidents; native-device testing remains separate. Briefly name PostgreSQL persistence, audited transitions and URL-served media.

Record at most three minutes. Do not display passwords, session cookies or private local configuration. The actual video and competition submission are performed separately by the owner.
